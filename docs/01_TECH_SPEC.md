# 01 — TECH SPEC: техническая документация

> Читается вместе с `00_README.md`, `02_STORY.md`, `03_GIFTS.md`. Приоритет документов — `00_README.md` §3.
> Ключевые слова: **ДОЛЖЕН** (обязательно), **СЛЕДУЕТ** (желательно), **МОЖЕТ** (по ситуации).
> Единицы: 1 unit = 1 метр, ось Y вверх. Время — секунды. Углы — градусы в конфигах, радианы в коде.

---

## 1. Цели и не-цели

**Цели.** Объёмное 3D-приключение 70–90 минут, 9 зон (CH00–CH08), данные-ориентированный квест-движок, интеграция физических подарков, фото-режим и финал, надёжные сохранения, деплой на существующий хостинг прототипа.
**Не-цели.** Мультиплеер, бэкенд, аккаунты, аналитика, мобильное управление (опционально, §2), боевая система, озвучка голосом, локализация.

## 2. Платформа и бюджеты

| Параметр | Значение |
|---|---|
| Браузеры | Chrome/Edge/Firefox (последние 2 версии), Safari 16+; **WebGL2 обязателен** |
| Устройства | Десктоп/ноутбук с клавиатурой (Q4). На touch/узком экране — экран `ui.mobile.warn` + режим «Эпилог без игры» (`?epilogue`) |
| FPS | ≥ 45 на интегрированной графике (класс Intel UHD 620) при пресете Low; ≥ 60 на среднем дискретном GPU |
| Вызовы отрисовки | ≤ 250 за кадр; видимые треугольники ≤ 400 000 |
| Текстуры | по умолчанию ≤ 1024²; «hero»-ассеты ≤ 2048²; формат KTX2/Basis или WebP |
| Первая загрузка до экрана «Начать» | ≤ 8 МБ (передано по сети) |
| Зона | ≤ 25 МБ на зону (сжато); весь проект ≤ 180 МБ |
| JS (стартовый чанк) | ≤ 900 КБ gzip, остальное — ленивые чанки |
| Память GPU | после выгрузки зоны возвращается к исходному уровню ±10% (проверка `renderer.info.memory`) |

## 3. Аудит прототипа (Фаза 0)

Прототип на `https://mtg-adm.ru/` (заглушка). Из публичного вида известно: ходьба WASD, взаимодействие **E**, выбор предмета **1–4**, использование **F**, закрытие диалога **Esc**, кнопка «Включить эмбиент», кнопка «Начать заново», миникарта (жёлтая точка — игрок), переменная высота рельефа, интерактивные объекты. **Исходный код агенту неизвестен до получения репозитория (Q2).**

**Задача аудита (T0.1).** Создать `docs/AUDIT.md`: стек (vanilla three / R3F / Rapier / иное), структура папок, как устроены: цикл, ввод, рельеф и высота, коллизии, интерактивы, диалоги, инвентарь, миникарта, аудио, сохранения, сборка и деплой, размеры бандла, FPS на тестовой сцене, список техдолга.
**Контракт совместимости.** Всё перечисленное в первом абзаце **ДОЛЖНО** сохраниться без изменений для игрока (клавиши, поведение, внешний вид HUD можно улучшать).
**Правило «перепиcывать или нет».** Переписывать с нуля **запрещено**, пока не выполнены ≥ 2 условий: (a) игровая логика неотделима от рендера; (b) интерактивы захардкожены в коде; (c) есть аллокации/утечки в цикле, дающие просадки FPS; (d) нельзя загрузить/выгрузить зону. Иначе — **инкрементальный рефакторинг** (strangler): новые модули рядом, старые заменяются по одному, после каждого шага игра запускается.
**Независимость от стека.** Спецификация не требует конкретного физдвижка: **ДОЛЖНЫ** быть реализованы интерфейсы `TerrainService.getHeightAt(x,z)` и `CollisionService` (§6), под ними допускается Rapier/ручные коллайдеры.

## 4. Архитектура

```
src/
  main.ts(x)            # точка входа, выбор маршрута: start | game | epilogue-only | mobile-warn
  app/                  # config.ts, router, bootstrap, StartGate
  engine/               # renderer, loop, input, audio, assets, quality, saveStorage
  world/                # ZoneManager, Terrain, PropsInstancer, Colliders, Atmosphere, Particles, Transitions
  gameplay/             # Player, Companions, Interaction, Inventory, Quest, Dialog, Effects, Abilities, Minigames/*
  ui/                   # HUD, DialogBox, Journal, WorldMap, GiftReveal, PhotoUI, MenuPause, LoadingScreen
  content/
    schema.ts           # типы данных (§8)
    items.ts            # реестр предметов
    chapters.ts         # цели и главы
    zones/<ZONE_ID>.json
    generated/          # dialogs.json, gifts.json (создаются скриптами, в git не коммитятся)
  dev/                  # debug API, fly-cam, overlays
scripts/                # content-sync.ts, check-consistency.ts, zone-gen.ts, optimize-assets.ts, strip-metadata.ts
docs/                   # четыре документа ТЗ (НЕ в public/)
public/                 # assets, art, audio, CREDITS.md, robots.txt
```

**Принципы.** (1) Игровое состояние живёт в **одном сторе** (`GameState`, §14), рендер лишь читает его. (2) Все события — через типизированный `EventBus`. (3) Контент — данные (JSON/TS + DLG), не код. (4) Любой интерактив/триггер/квест описывается в данных; код знает только «виды» (`kind`). (5) Каждое действие игрока сводится к списку `Effect` (§8).

## 5. Цикл, ввод, клавиши

Фиксированный шаг логики 60 Гц, рендер — `requestAnimationFrame`, при скрытой вкладке — пауза. Δt ограничен 0.05 с.

| Клавиша | Действие вне диалога | В диалоге |
|---|---|---|
| W A S D / стрелки | движение | выбор варианта (W/S) |
| Shift | бег (зажать) | — |
| Мышь (ЛКМ-перетаскивание или ПКМ) | поворот камеры | — |
| E | взаимодействие/подбор | далее / подтвердить выбор |
| 1–4 | выбрать предмет хотбара | выбрать вариант ответа 1–4 |
| F | использовать выбранный предмет на цели; удерживать (мини-игры) | — |
| Q | способность спутника (Бацзе «Нюх»; Сунь «Облако» — на `cloud_spot`) | — |
| J | журнал (цели, мешок, камера, печати) | — |
| M | карта мира (пергамент) | — |
| Esc | пауза/закрыть окно | закрыть (не пропускает реплики-развилки) |
| F9 | debug-оверлей (только с `?debug=TOKEN`) | — |

Конфликт 1–4: в диалоге числа выбирают ответ, вне диалога — предмет. Подсказки клавиш показываются в HUD по контексту. Прыжка нет, если его нет в прототипе (решает аудит).

### 6.3 Рельеф и коллизии

- `TerrainService.getHeightAt(x,z)`: билинейная выборка heightmap; кэширование; тот же источник для меша и физики.
- Меш рельефа: сетка чанков 4×4 (по 64×64 вершин), 3 уровня LOD, перекрытие швов, нормали из карты высот. Склон > `slopeMaxDeg` = скольжение вниз (без урона).
- `CollisionService`: статические препятствия — окружности/боксы по XZ (2D) + высота; динамика не нужна. Если прототип использует Rapier — допускается через него.
- Поверхности (`surfaceMap`): множитель скорости (снег 0.9, песок 0.8, лёд 1.0 со скольжением), звук шагов, опасные (лава, тонкий лёд) = мягкий респаун на ближайший чекпоинт с репликой `ui.respawn`.
- Уровни/этажи (пещера): `levels` в JSON — плоскости с собственными heightmap; переход через лестницы/склоны.

### 6.4 Загрузка/выгрузка зон

- `ZoneManager.load(zoneId)`: экран загрузки с прогрессом; приоритет — рельеф, коллайдеры, интерактивы, затем декор.
- **Предзагрузка** следующей зоны стартует при выполнении 50% целей текущей главы, в фоне (низкий приоритет, не блокирует кадр).
- **Выгрузка** предыдущей зоны **ДОЛЖНА** вызывать `dispose()` геометрий/материалов/текстур, останавливать частицы и аудио, очищать подписки.
- **Переходы:** CH00–CH03 — `walk_fade` (затемнение при выходе в триггер); с CH04 — `sleigh` (20–30 с кат-сцены: Бай-Лун тянет сани, камера следует маршрутом по глобальной карте; **пропускается** по Esc/кнопке). Во время перехода грузится следующая зона.

## 7. Игрок, камера, спутники

- Скорость: ходьба 4.5 u/s, бег 7 u/s; ускорение/торможение гладкие; поворот модели к направлению движения (slerp).
- Камера: третье лицо, расстояние 6–9, вертикаль 15–70°, демпфирование; не проходит сквозь рельеф (сфера-каст по heightfield); в узких местах приближается.
- Анимации: клипы `idle/walk/run` из GLB или процедурный fallback (покачивание, наклон).
- Спутники (`СУНЬ`, `БАЦЗЕ`, `ША`, `БАЙЛУН`): следование за игроком по пружине с дистанцией 2–4 м, смещение влево/вправо, подпрыгивание на неровностях; телепорт к игроку при отставании > 25 м; в диалогах поворачиваются к собеседнику.
- Способности: **Сунь «Облако»** — на `cloud_spot` по Q появляется облако-платформа (анимация), игрок переносится по дуге; **Бацзе «Нюх»** — Q, радиус 25 м, подсветка скрытых предметов 5 с, перезарядка 20 с; **Ша Сэн «Мост»** — на `bridge_spot` по Q выдвигается мост 8 м; **посох (F)** — заморозка воды/лавы на 12 с на объектах с `freezable: true`.

## 8. Квест-движок

### 8.1 Типы данных (`src/content/schema.ts`)

```ts
export type Id = string;
export type Condition =
  | { flag: string }
  | { notFlag: string }
  | { item: string; count?: number }          // count по умолчанию 1: «не менее»
  | { objective: Id; state: 'active' | 'done' }
  | { all: Condition[] }
  | { any: Condition[] };

export type Effect =
  | { type: 'setFlag'; flag: string }
  | { type: 'unsetFlag'; flag: string }
  | { type: 'giveItem'; item: string; count?: number }
  | { type: 'takeItem'; item: string; count?: number }
  | { type: 'activateObjective'; id: Id }
  | { type: 'completeObjective'; id: Id }
  | { type: 'startDialog'; id: Id }
  | { type: 'addCompanion'; id: string }
  | { type: 'stamp'; id: string }                 // S01..S08
  | { type: 'showGift'; id: string }              // G00..G07
  | { type: 'startMinigame'; id: string }         // MG_*
  | { type: 'unlock'; id: Id }                    // показать/включить интерактив
  | { type: 'completeChapter' }
  | { type: 'playSfx'; id: string }
  | { type: 'save' }
  | { type: 'if'; cond: Condition; then: Effect[]; else?: Effect[] };

export interface ObjectiveDef {
  id: Id; text: string; hidden?: boolean; counter?: { item?: string; flagPrefix?: string; target: number };
  marker?: { pos: [number, number, number] | null }; // стрелка/метка на миникарте
}

export interface ChapterDef {
  id: 'CH00'|'CH01'|'CH02'|'CH03'|'CH04'|'CH05'|'CH06'|'CH07'|'CH08';
  zone: string; title: string; subtitle?: string;
  objectives: ObjectiveDef[];
  onEnter: Effect[]; onComplete: Effect[];
  gift?: string; stamp?: string; next?: string;
}

export interface InteractableDef {
  id: Id; kind: 'dialog'|'pickup'|'use_target'|'gate'|'cooking'|'trade'|'shrine'|'viewpoint'|'workbench'|'sign'|'checkpoint'|'freezable';
  model?: string; pos: [number, number, number]; rotY?: number; radius: number; prompt: string;
  requires?: Condition; once?: boolean; hiddenUntil?: Id; hintable?: boolean; // для «Нюха»
  useItem?: { item: string; effects: Effect[] };
  effects: Effect[];
}

export interface ItemDef { id: string; name: string; desc: string; category: 'tool'|'bag'|'key'; icon: string; maxStack?: number; }
```

### 8.2 Правила исполнения

- Эффекты исполняются **последовательно и синхронно**; кат-сцены и диалоги — блокирующие (очередь).
- Эффекты **идемпотентны**: повторное `giveItem` ключевого предмета не дублирует (проверка по `maxStack`/категории).
- Квест считается завершённым, когда `completeObjective` вызван для всех не-`hidden` целей главы **и** вызван `completeChapter`.
- Подписки на события: `interact(id)`, `npc(id)`, `trigger(id)`, `event(name)`, `item:changed`, `flag:changed`, `minigame:done(id)`.
- Чекпоинты: автосохранение по вызову `save`, при вхождении в `checkpoints[]`, на завершении цели.
- Мягкий провал: респаун на последний чекпоинт без потери инвентаря и целей.

## 9. Диалоги: формат DLG

Диалоги хранятся в `02_STORY.md` внутри блоков ```` ```dlg ````. Скрипт `content-sync` собирает их в `generated/dialogs.json` и **валидирует**.

### 9.1 Грамматика

```
@dialog <ID>                      # CHxx.Dyy
@trigger interact:<OBJ> | npc:<NPC> | event:<NAME> | chain
@priority <int>                   # по умолчанию 0; при совпадении триггеров побеждает больший, затем порядок в файле
@requires flag:<name> | !flag:<name> | item:<ITM> | item:<ITM>>=<N>   # несколько строк = И
@repeat once | always             # по умолчанию always
<СПИКЕР>: <текст>                 # текст ≤ 220 символов; допустимы {{kid}} и *ремарка*
? <вопрос>                        # блок выбора (2–4 пункта)
- <текст варианта> -> <МЕТКА>     # пункт выбора
:<МЕТКА>                          # метка перехода
!set <flag>                       # эффекты (строки на «!»)
!unset <flag>
!give <ID> [N]      !take <ID> [N]
!obj <CHxx.Oyy> activate|done
!companion add <КОД_СПИКЕРА>
!stamp <Sxx>        !gift <Gxx>
!minigame <MG_ID>   !unlock <OBJ_ID>
!next <ДИАЛОГ_ID>   # запустить следующий диалог после закрытия текущего
!goto <МЕТКА>
!chapter complete
@end
```

### 9.2 Правила и проверки

1. Спикеры только из реестра `00_README.md` §4.4. Неизвестный спикер — ошибка сборки.
2. Каждая метка достижима; `!goto`/`-> LABEL` ссылаются на существующие метки внутри диалога.
3. Все `!give/!take/@requires item` ссылаются на предметы из `items.ts`; `!stamp/!gift` — на существующие S/G; `!minigame` — на зарегистрированные MG.
4. `@trigger event:` имеет производителя (таблица `02_STORY.md` §11). `@trigger chain` запускается только через `!next`.
5. Выбор диалога выполняется без утечки состояния: эффекты после метки исполняются при её достижении.
6. Если несколько диалогов подходят под один триггер, выбирается: наибольший `@priority`, затем первый по файлу; `@repeat once` после проигрыша не участвует.
7. `{{kid}}` подставляется из `config.recipient.address` (по умолчанию «внучок»).

### 9.3 UI диалога

Нижняя панель: портрет/иконка + имя + текст с «печатью» 35 символов/с; E — досмотреть/далее, повторное E — следующая реплика; варианты показываются списком 1–4; камера слегка приближается к собеседнику; игрок неподвижен; Esc закрывает (кроме развилок). Не более 3 строк, иначе авто-разбивка.

## 10. Инвентарь, журнал, карта

- **Хотбар (tool):** 4 слота, выбор 1–4; выбранный подсвечен; F применяет к цели (`useItem`). В хотбаре никогда не больше 4 `tool` (проверяет `check:content` по `chapters.ts`/диалогам).

- **Цели:** трекер слева вверху (макс. 3 активные цели), счётчики «(0/5)».
- **Миникарта:** сохраняется из прототипа; для каждой зоны — top-down рендер в текстуру при загрузке; метки целей.
- **Карта мира (M):** пергамент, маршрут по узлам из `02_STORY.md` §3; пройденные — яркие, будущие — полупрозрачные; текущая зона мигает.

## 11. Интеграция подарков

### 11.1 Контент-пайплайн

1. `npm run content:sync` читает `docs/03_GIFTS.md`, берёт блок ```` ```yaml data:gifts ````, валидирует и пишет `src/content/generated/gifts.json`.
2. `unlock.code` и `start_gate.phrase` **нормализуются** (верхний регистр, `ё→е`, пробелы убраны) и **хэшируются** (SHA-256 + соль из `config.ts`); в клиент попадает только хэш. Открытые коды в `public/` и в `dist/` **не должны** присутствовать (проверка `check:content` по строкам).
3. `docs/` не копируется в `public/` и `dist/`.

### 11.2 Стартовый экран (StartGate)

Поле «Введи слово с открытки» (`ui.start.gate`). Режимы `soft|hard|off`. По умолчанию `soft`: после `skip_after_sec` появляется «У меня нет открытки». Ошибочное слово — шутливая реплика Деда Мороза, без блокировки.

### 11.3 Окно раскрытия подарка (GiftReveal)

Триггерится эффектом `showGift` (после закрытия диалога). Содержит: заставку `reveal.image`, заголовок, текст из `03_GIFTS.md`, надпись `ui.gift.open` («Достань конверт №N»), поле ввода слова-кода (если `unlock.mode != off`), кнопки «Дальше» и (через `skip_after_sec`) «У меня нет конверта».
Правильный код → анимация печати `Sxx` (штамп в грамоту) + реплика `ДМ: Ага, значит, посылочка дошла!`; неверный — шутливый отказ; прогресс **никогда** не блокируется при `soft`.

### 11.4 Журнал «Грамота»

Показывает рисунок G01 (если есть), 8 слотов печатей, дату получения каждой печати (локальная, без внешних данных).

### 11.5 Режим «парашюта»

- Параметр `?epilogue` ведёт сразу на финальный экран (фото + титры) без игры — для телефонов/сломанного WebGL.
- Если WebGL2 недоступен: статическая страница с подписью, финальным полароидом и сообщением «Открой главную коробку».
- Все «нужные» подарки лежат в посылке независимо от сайта (`03_GIFTS.md` §1).

## 12. Фото-режим и финал (`MG_PHOTO`)

**Вход:** на `OBJ_VIEWPOINT_FOREST` / `OBJ_VIEWPOINT_MOUNTAIN` с `KEY_CAMERA` в инвентаре. Камера на штативе, игрок «заморожен», управление: мышь — наведение, колесо — зум (FOV 20–60°), `Shift` — фокус «плавно», `E` — кадр, `Esc` — выйти.
**Видоискатель:** рамка 3:2, сетка третей, индикаторы.
**Оценка кадра (0–100):** считается на кадре захвата:
- Композиция (до 40): центр цели в зоне третей — линейный спад от идеальных точек.
- Цели в кадре (до 40): список `subjects` точки (пики, лес, водопад, птицы, спутники) — по 8–10 очков за каждую, видимую во фрустуме и не закрытую рельефом (raycast).
- Освещение/туман (до 20): «золотой час» — окно по времени сцены; туман приемлемый.
Порог «хорошо» — ≥ 60 (триггерит `MG_PHOTO_DONE` при первом таком кадре). Кадров можно делать сколько угодно (галерея 6 шт.).
**Время суток:** на точке доступны ползунок «рассвет → золотой час» и таймер; МОЖЕТ быть упрощён до фиксированного рассвета.
**Захват кадра:** рендер в `WebGLRenderTarget` 1800×1200 → `canvas` → PNG; без метаданных; рамка полароида — CSS/canvas поверх.
**Проявка:** анимация 4 с (blur+sepia → резкость), текст «Лесистые предгорья · Анонимный Дед Мороз», событие `PHOTO_DEVELOPED`.
**Финал:** экран с полароидом + кнопки «Сохранить снимок» и «Титры», подарок G00 (`showGift`), печать S08, тексты `02_STORY.md` §6.
**Официальный арт карты в игре не используется** (Q10).

## 13. Визуал, VFX, аудио

**Стиль:** low-poly, плоское затенение, цвет вершин, градиентное небо, мягкий туман, тёплые источники света. Допустим лёгкий контур у интерактивов. Постэффекты: Bloom (лава, фонари), виньетка; на пресете Low отключены.
**Частицы (пресеты):** `snow_light`, `snow_heavy`, `ice_sparkles`, `dust_wind`, `embers`, `spores`, `fireflies_day`, `lanterns_float`, `mist`, `birds`. Реализация — GPU-инстансинг/Points; бюджет ≤ 3 000 частиц одновременно.
**Ассеты:** сторонние только CC0/CC-BY (Quaternius, Kenney, Poly Haven, Sketchfab с лицензией CC) + собственные примитивы; все — в `public/CREDITS.md` (источник, автор, лицензия, ссылка). Обязательный fallback — примитивные модели из `BoxGeometry/Cylinder/Cone`, если GLB не загрузился.
**Модели:** GLB, ≤ 30k треугольников на персонажа, Draco + KTX2 (`scripts/optimize-assets.ts`), метаданные автора очищаются.
**Аудио:** `.ogg` (+ `.mp3` fallback для Safari), эмбиент на зону ≤ 1.5 МБ, кроссфейд 2 с между зонами; SFX-пул; звук включается после первого жеста (кнопка «Включить эмбиент» сохраняется); общий mute и громкость; позиционное аудио для костра/воды/фонарей (МОЖЕТ).
**Пресеты качества:** Low/Medium/High; авто-выбор по тестовому прогону 2 с при старте; адаптивное DPR (1.0–2.0), снижающееся при FPS < 40 в течение 2 с, возвращающееся при FPS > 58.
**Доступность:** опция «Меньше эффектов» (отключает bloom, тряску, плотные частицы), уважает `prefers-reduced-motion`; субтитров не требуется (нет озвучки).

## 14. Сохранения

```ts
interface SaveV1 {
  v: 1; savedAt: string;               // ISO, локальное время
  chapter: string; zone: string; pos: [number, number, number];
  flags: Record<string, true>;
  items: Record<string, number>; hotbar: (string|null)[];
  objectives: Record<string, 'active'|'done'>;
  companions: string[]; stamps: string[]; giftsShown: string[]; giftsUnlocked: string[];
  dialogsPlayed: string[]; minigames: Record<string, { done: boolean; attempts: number }>;
  settings: { quality: 'auto'|'low'|'med'|'high'; musicVol: number; sfxVol: number; reduceFx: boolean };
}
```
- Ключ `localStorage`: `adm.save.v1`. Автосохранение с троттлингом 5 с + при чекпоинтах/целях/закрытии вкладки (`pagehide`).
- Экспорт/импорт: кнопка «Скопировать код прогресса» (base64 от сжатого JSON); импорт валидирует версию и ID.
- Миграции: `migrate(save)` по версии; **ID не переименовываются после выдачи ссылки получателю** без миграции.
- «Начать заново» требует подтверждения и не удаляет настройки.
- Нет доступа к `localStorage` (инкогнито/запрет) → прогресс держится в памяти, показывается предупреждение и кнопка экспорта.

## 15. Производительность

- Инстансинг (`InstancedMesh`) для деревьев, камней, фонарей, дюн; слияние статичной геометрии; общие материалы.
- Frustum culling + дальность отрисовки по `fog.far`; чанки рельефа с LOD.
- Тени: один источник, карта ≤ 2048, каскады не нужны; на Low тени выключены, добавляется «пятно-blob» под персонажами.
- Нет аллокаций в `update` (векторы переиспользуются), пулы для частиц/эффектов.
- Лоадер: `KTX2Loader` + `DRACOLoader` с локальными декодерами в `public/`.
- Пауза рендера/логики при `document.hidden`; аудио приглушается.
- Бюджет проверяется встроенным оверлеем `?debug`: FPS, draw calls, tris, память GPU, активные частицы.

## 16. Приватность и анонимность (блокирующие требования)

1. **Ноль внешних запросов**: шрифты (самохост WOFF2), библиотеки (бандл), медиа, карты — всё на своём домене. CSP это подтверждает (§17).
2. **Никаких метаданных автора**: чистка EXIF/XMP у изображений и метаданных GLB (`scripts/strip-metadata.ts`), удалены `<meta name="author">`, комментарии в HTML/CSS/JS, названия файлов без имён; `sourcemap: false` в продакшене; в сборке нет путей с именем пользователя ОС.
3. **Git/деплой:** git-авторство репозитория может быть любым, но **в деплой попадает только `dist/`**; `docs/`, `.git`, `.cursor`, `scripts/`, `.env` — не публикуются.
4. **Индексация:** `robots.txt` `Disallow: /`, заголовок `X-Robots-Tag: noindex, nofollow, noarchive`, `<meta name="robots" content="noindex,nofollow">`.
5. **Сервер:** если на IP/сертификате/конфиге nginx есть другие ваши проекты, получатель потенциально может их найти через reverse-IP/Certificate Transparency. Мера: отдельный `server_name` без wildcard-сертификата, отдельный сертификат для домена игры, WHOIS-приватность, отсутствие ссылок на другие проекты, отключённый листинг каталогов, `server_tokens off`.
6. **Тексты:** только «Сибирь», без городов; подпись — «Анонимный Дед Мороз» (`02_STORY.md` §1).
7. **Нет логирования в клиенте:** `console.log` только в dev; в проде тихий режим.
8. **Режим отладки** включается только при `?debug=<TOKEN>` и записи флага в `sessionStorage`, токен — из переменной окружения сборки; без токена API отсутствует.

## 20. Риски

| Риск | Вероятность | Мера |

| Слишком большие зоны, FPS низкий | средняя | чанки/LOD/инстансинг, пресеты качества, возможность уменьшить зоны на 20–30% |

| Получатель не может открыть сайт | низкая | `?epilogue`, посылка самодостаточна |
| Потеря прогресса | средняя | автосохранение, экспорт кода |
