# AUDIT — аудит прототипа (T0.1)

Дата: 2026-11-05. Исходник прототипа: `legacy/prototype.html` (в деплой не попадает).

## 1. Стек и структура

| Пункт | Прототип |
|---|---|
| Стек | vanilla three.js 0.160.1, ES-модуль с jsDelivr (внешний запрос — нарушает README §5.3) |
| Структура | один HTML-файл ≈ 4 360 строк / 94 КБ: CSS + разметка HUD + один `<script type="module">` |
| Сборка | нет; локальный запуск `python -m http.server` (`legacy/start.bat`) |
| Деплой | статическая раздача nginx |

## 2. Подсистемы

| Подсистема | Как устроено в прототипе |
|---|---|
| Цикл | `requestAnimationFrame(frame)`, переменный шаг, логика и рендер смешаны в `frame()` |
| Ввод | `keydown/keyup` → набор нажатых клавиш; WASD/стрелки, E, 1–4, F, Esc |
| Рельеф | аналитическая функция `terrainHeight(locationId,x,z)` из суммы «холмов»; меш — `PlaneGeometry` |
| Коллизии | 2D-окружности и боксы по XZ (`circleCollider`, `boxCollider`), проверка `validPlayerPosition` |
| Интерактивы | `register({...})` с замыканиями-обработчиками прямо в коде; ветвления по `state.flags` |
| Диалоги | модальное окно `showModal(title, text, actions)`; тексты захардкожены |
| Инвентарь | массив из 4 слотов, предметы-эмодзи |
| Миникарта | `<canvas>` 2D, перерисовка каждый кадр, жёлтая точка — игрок |
| Аудио | процедурный эмбиент на WebAudio, включается кнопкой «Включить эмбиент» |
| Сохранения | `localStorage` `anonymous-santa-three-v2`, ручная валидация |
| Локации | 3 локации в одной сцене со смещением `baseX` (0/70/140), размер 44×44 м, выгрузки нет |
| Камера | третье лицо, фиксированный наклон, следование через `lerp` |

## 3. Замеры

- Размер: 94 559 байт HTML + three.js с CDN (~650 КБ несжатого).
- Draw calls: каждый примитив — отдельный `Mesh` без инстансинга (деревья, камни, частицы).
- Тени: `PCFSoftShadowMap` 2048², один направленный свет.

## 4. Решение «переписывать или рефакторить» (TECH §3)

Выполнены условия:
- **(a)** логика неотделима от рендера (`frame()` двигает игрока, проверяет квест и рисует миникарту);
- **(b)** интерактивы захардкожены (`register` с замыканиями, ветки по флагам);
- **(d)** зоны нельзя загрузить/выгрузить (все локации живут в одной сцене).

Три условия из четырёх ⇒ **переписываем** на Vite + TypeScript по архитектуре TECH §4. Из прототипа переносятся визуальный язык (low-poly примитивы, палитра `MAT`, модели Деда Мороза и людей), HUD-стиль панелей и контракт управления.

**Контракт совместимости, который сохраняется:** WASD/стрелки, E, 1–4, F, Esc, миникарта (жёлтая точка — игрок), кнопки «Включить эмбиент» и «Начать заново».

## 5. Техдолг прототипа (не переносится)

- Внешний CDN three.js; эмодзи как иконки (зависят от шрифтов ОС).
- Нет инстансинга и `dispose()`.
- Сохранение без версий и миграций.

## 6. Деплой и хостинг

- Схема по TECH §17: `/var/www/adm/releases/<UTC-timestamp>` + симлинк `/var/www/adm/current`, nginx `root /var/www/adm/current`. Хранятся 3 релиза.
- Репозиторий `/opt/ADM` **не раздаётся** веб-сервером (до 2026-11-05 раздавался — ТЗ были доступны по `/info/`; закрыто).
- Принятый автором риск (2026-11-05): IP `31.56.208.62` общий с другими проектами автора; виден через reverse-IP. Сертификат для `mtg-adm.ru` отдельный, без wildcard; `server_tokens off`.

## 7. Отклонения реализации от TECH (согласованные)

- **Рельеф без PNG-карт высот.** Вместо `heightmap`/`surfaceMap` зона описывает процедурный рельеф (`terrain.gen`: seed, шум, площадки, пандусы) и поверхности списком фигур (`surfaces`). Карта высот генерируется при загрузке в `Float32Array`, `TerrainService.getHeightAt` — билинейная выборка по ней (тот же источник для меша и физики). Это допускается TECH §3 «независимость от стека» и §6 `zone-gen.ts`.
- **Этажи пещеры** — террасы рельефа на трёх высотах, соединённые пандусами (без отдельных heightmap на этаж).
- **Модели** — процедурные low-poly примитивы (обязательный fallback TECH §13), GLB-загрузка поддержана, но не обязательна.
- **Аудио** — процедурный синтез WebAudio (эмбиенты, SFX, мотивы), без сторонних файлов ⇒ нет лицензионных рисков.

## Деплой (T9.2)

- `npm run deploy -- prod|staging`, `bash scripts/deploy.sh rollback [prod|staging]`, `bash scripts/deploy.sh list [prod|staging]`.
- Прод: `/var/www/adm/releases/<ts>` + симлинк `current`; staging: `/var/www/adm/staging-releases/<ts>` + симлинк `staging`, URL `/staging/` за Basic Auth (`/etc/nginx/adm-staging.htpasswd`, пароль у владельца сервера). Хранятся 3 последних релиза.
- После выкладки скрипт проверяет `curl -I`: 200, CSP, X-Robots-Tag, Referrer-Policy, отсутствие версии nginx и sourcemap, `robots.txt`.
- Копия конфигурации nginx — `docs/nginx/`. CSP на проде включается заменой `set $adm_csp "";` на `include snippets/adm-csp.conf;` — включено.
- Debug API попадает только в сборки с `VITE_DEBUG_TOKEN` (e2e и staging с `STAGING_DEBUG_TOKEN`); прод-сборка проверяется скриптом.

## Модели (T7.2)

- Персонажи и пропсы — процедурные low-poly модели из примитивов (`src/world/Models.ts`), это обязательный fallback по TECH §13. Сторонних GLB нет, поэтому `CREDITS.md` содержит только собственные ассеты. Замена на CC0-модели возможна позже без изменения контента (ключи `model`/`asset` в зонах).
- Статичные пропсы зоны запекаются по материалу в ячейках 64 м (`bakeStatic`), бюджет ≤ 250 draw calls соблюдается во всех зонах (оверлей `?debug`).
